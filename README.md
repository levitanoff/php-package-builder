# PHP Package Builder

Сборка нативных пакетов PHP через Docker для обновления существующих серверов
и образов PHP-FPM для подготовки переноса сайтов. Пакетный backend выдаёт `.deb`,
контрольные суммы и логи; runtime-backend — образ для запуска приложения.

Проект начинает с одной конкретной цели. Новые сочетания PHP, Debian и архитектуры
добавляются отдельными профилями после проверки исходников и совместимости.

| Профиль | Целевая система | PHP | Архитектура | Состояние |
| --- | --- | --- | --- | --- |
| `debian10-php8.3.36-amd64` | Debian 10 Buster | 8.3.36 | amd64 | Экспериментальный: полная сборка пока не подтверждена |

Отдельный runtime-профиль `debian13-php5.6.40-fpm-amd64` собирает образ
PHP 5.6-FPM с закреплёнными пакетами, содержащими backport для PHP2Shell:

```bash
./bin/php-runtime build debian13-php5.6.40-fpm-amd64
```

Он проверяет расширения legacy-приложений, cp1251, реальный FPM, загрузки
файлов и поведение backport при OOM. Совместимость приложения ещё не подтверждена.
[Сборка и границы PHP 5.6 runtime](docs/php56-runtime.md).

## Быстрый запуск

Требуются Linux, Python 3.8+ и работающий Docker Engine с доступом текущего
пользователя. Дополнительные Python-пакеты не нужны. Рекомендуется собирать
на рабочей или выделенной сборочной машине с запасом диска и памяти.

```bash
./bin/php-build list
./bin/php-build check
./bin/php-build build debian10-php8.3.36-amd64 --jobs 2
```

Команда загружает проверенные по SHA256 исходники, создаёт контекст, запускает
Docker-сборку с целевой платформой и экспортирует артефакты. Лог одновременно
выводится на экран и сохраняется на диск. Ошибка сборки останавливает процесс.

Результат находится в `out/<профиль>/<отпечаток-входных-данных>/`:

- нативные `.deb`, `.changes` и `.buildinfo`;
- `SHA256SUMS` и `package-manifest.txt`;
- `profile.json`, `build-report.json`, `build.log`, `php-tests.log`.

Повторное получение пакетов из уже собранного образа:

```bash
./bin/php-build export debian10-php8.3.36-amd64
```

## Уже скачанные исходники

Можно использовать каталог `sources` из первоначального комплекта сборки:

```bash
./bin/php-build build debian10-php8.3.36-amd64 --jobs 2 \
    --sources-dir ../php83-buster-builder/sources --offline
```

Здесь `--offline` запрещает скачивание **исходников**. Docker всё ещё может
загружать базовый образ и APT-зависимости. Подмена исходных файлов или повреждение
кеша обнаруживаются по контрольным суммам.

Подготовить контекст без запуска Docker:

```bash
./bin/php-build prepare debian10-php8.3.36-amd64 \
    --sources-dir ../php83-buster-builder/sources --offline
```

## Устройство проекта

| Каталог / файл | Назначение |
| --- | --- |
| `profiles/*.json` | Версия PHP, исходники, целевая система, архитектура и проверки |
| `docker/Dockerfile` | Общая процедура сборки Debian-пакетов |
| `scripts/verify-build.sh` | Проверки внутри целевого контейнера |
| `builder.py`, `bin/php-build` | Подготовка, Docker-сборка, логирование и экспорт |
| `tests/` | Проверки профилей, целостности исходников и поведения сборочной команды |
| `runtimes/`, `runtime_builder.py`, `bin/php-runtime` | Отдельные рецепты и профили образов для запуска PHP-FPM |
| `docs/` | Контракты профилей и порядок проверки пакетов перед установкой |

Исходные архивы хранятся в `.cache`, контексты и промежуточные логи — в `.work`.
Эти каталоги и `out` исключены из Git. Образ получает имя с отпечатком профиля,
Dockerfile и скрипта проверок, чтобы изменения рецепта выбирали другой образ.
Пакеты извлекаются через `docker cp` из созданного, но не запущенного контейнера.

## Границы первой версии

- Реализован Debian-backend; исходная упаковка берётся из Sury и пересобирается
  на целевой Debian с вычислением его зависимостей.
- Первый профиль пересобирает исходный пакет Sury для Debian 11 на Debian 10.
  Версия `8.3.36-1~deb10.local1` выше установленной ранее 8.3.8; понижение
  номера относительно исходного пакета явно разрешено в `dch`.
- Проверяются CLI, FPM, модуль Apache, загрузка указанных расширений,
  архитектура/версия пакетов и выбранные upstream-тесты PHP.
- Redis, igbinary, Imagick и другие PECL-модули требуют отдельных проверок
  и при необходимости отдельных рецептов сборки.
- Добавление архитектуры в профиль само по себе не доказывает поддержку:
  потребуется нативная машина или настроенная эмуляция и успешный прогон.
- Полная сборка первого профиля ещё не подтверждена. В среде подготовки
  проверены исходники, применение патчей, подготовка контекста и проверки
  управляющего кода; Docker Engine там отсутствует.
- Профиль фиксирует исходники, но пока использует тег базового образа и
  APT-репозитории. Побитовая воспроизводимость результата не заявляется.

Процедура установки выполняется отдельно после проверки пакетов и приложения:
[проверка перед установкой](docs/install-validation.md).

## Развитие

Ближайшая цель — довести первый профиль до успешной сборки и проверить пакеты
на копии целевой системы. Затем добавлять профили для других PHP/Debian,
проверки PECL, закрепление digest базовых образов и при необходимости отдельные
backend для Ubuntu или других форматов пакетов.

Для работы с кодом:

```bash
python3 -m unittest discover -s tests -v
./bin/php-build check
./bin/php-runtime check
```

Происхождение и лицензии PHP и упаковки сохраняются в исходных пакетах
и сформированных пакетах. В репозиторий исходные архивы не включаются.
