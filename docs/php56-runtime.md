# PHP 5.6-FPM для переноса legacy-приложений

Экспериментальный профиль `debian13-php5.6.40-fpm-amd64` собирает **образ для
запуска**, используя готовые пакеты PHP. Он не пересобирает PHP из исходников
и не устанавливает пакеты на хост. ОС внутри образа — Debian 13 Trixie; сервер
не обязан работать на том же Debian.

## Источник PHP и границы исправления

PHP 5.6 не поддерживается upstream. Используется пакет Sury
`5.6.40-105+0~20261022.135+debian13~1.gbp37a17e` с backport для
`CVE-2026-109618` и `CVE-2026-109619`. Новый номер PHP `5.6.41` не существует:
проверять только вывод `php -v` недостаточно.

В исходной упаковке проверен файл
`debian/patches/0261-Avoid-state-corruption-via-bailout.patch`, обозначенный
сопровождающими как `Minimal mitigation for EOL version`. Это другой механизм,
чем полное исправление в поддерживаемых PHP 8.x: OOM немедленно завершает
процесс, обработчики shutdown не вызываются, session upload progress отключён
в исходном коде. Обычные загрузки файлов сохраняются. Приложение не должно
рассчитывать на shutdown-обработчик после исчерпания памяти.

Источники:

- [Объявление PHP](https://www.php.net/archive/2026.php).
- [CVE-2026-109618](https://github.com/php/php-src/security/advisories/GHSA-w8hw-w9fx-j79w).
- [CVE-2026-109619](https://github.com/php/php-src/security/advisories/GHSA-6wmf-4rv5-p3rp).
- [Исходная упаковка проверенного пакета](https://packages.sury.org/php/pool/main/p/php5.6/php5.6_5.6.40-105%2B0~20261022.135%2Bdebian13~1.gbp37a17e.debian.tar.xz).
- [Настройка подписанного репозитория Sury](https://packages.sury.org/php/README.txt).

SHA256 каждого PHP-пакета и пакета ключей закреплён в JSON-профиле. При
подготовке контекста и внутри Docker проверяются байты пакетов; внутри образа
также проверяются точная ревизия и архитектура. Остальные зависимости получает
APT с проверкой подписей Debian и Sury. Если закреплённый пакет исчезнет из
репозитория, сборка завершится ошибкой, без перехода на другую версию.

Тег базового Debian и версии зависимостей пока не закреплены digest/snapshot:
побитовая воспроизводимость образа не заявляется. Добавление другого поставщика
PHP требует отдельного рецепта; текущий проверяет происхождение пакетов Sury.

## Сборка

Требуются Linux, Python 3.8+ и Docker:

```bash
./bin/php-runtime list
./bin/php-runtime check
./bin/php-runtime build debian13-php5.6.40-fpm-amd64
```

Имя образа включает отпечаток профиля и всех файлов рецепта. Узнать его:

```bash
php56_image="$(./bin/php-runtime image debian13-php5.6.40-fpm-amd64)"
docker run --rm --network none "$php56_image" php5.6 -v
docker run --rm --network none "$php56_image" php5.6 -m
```

Профиль, перечень установленных пакетов и результат контейнерных проверок
также лежат в `/usr/local/share/php-runtime/` внутри образа. Локальный отчёт
и лог появляются в `out/runtimes/<профиль>/<отпечаток>/` только после успешной
сборки. Отчёт явно оставляет проверки приложения и полный security-аудит
невыполненными.

```bash
./bin/php-runtime prepare debian13-php5.6.40-fpm-amd64
./bin/php-runtime prepare debian13-php5.6.40-fpm-amd64 --offline
```

`--offline` запрещает скачивать входные PHP-пакеты и пакет ключей. При сборке
Docker и APT по-прежнему могут использовать сеть. Подготовка работает без Docker.

## Что проверяет сборка

- PHP 5.6.40 NTS и module API `20131226`.
- `mysql_*`, mysqli, PDO MySQL, mbstring, iconv, DOM/XML/XSL, JSON, GD и OPcache.
- GD с JPEG, PNG и FreeType; преобразование и изменение регистра cp1251.
- Реальный FPM-процесс, запросы FastCGI и короткие PHP-теги.
- Обычная multipart-загрузка файла.
- Отсутствие записи session upload progress даже при принудительном включении
  этой функции в тестовом пуле и отключении очистки progress-записей.
- Завершение CLI при OOM с ожидаемым кодом и без shutdown-callback.
- Завершение FPM-воркера при OOM, отсутствие shutdown-callback и обслуживание
  следующего запроса новым воркером.

Последняя стадия Dockerfile зависит от стадии проверок: ошибка любой из них
не позволяет получить итоговый образ. Python и тестовые PHP-скрипты остаются
в промежуточной стадии и не попадают в конечный runtime.

Эти проверки подтверждают конкретные свойства образа и backport. Они не
доказывают отсутствие всех вариантов эксплуатации или других уязвимостей PHP 5.6.

## Подключение приложения

FPM запускается в foreground, обслуживает TCP 9000 и использует пользователя
`www-data` для воркеров. Для Docker Compose его порт не следует публиковать
на хосте: Nginx подключается по общей Docker-сети. Код приложения монтируется
в `/var/www/html`; в образ он не копируется.

Проектный PHP INI можно подключить отдельно в
`/etc/php/5.6/fpm/conf.d/zz-site.ini`, для CLI — в соответствующий `cli/conf.d`.
Базовый рецепт включает короткие теги, но не устанавливает глобальную cp1251:
смешанные публичные страницы, XML и административные интерфейсы нужно проверить
отдельно. Проверка конвертации cp1251 не является проверкой HTTP-кодировки сайта.

Параметры пула, лимиты загрузок и памяти — начальные значения рецепта.
Production-настройки зависят от приложения и ресурсов сервера. База данных,
миграция её кодировки, cron, почта, пути записи и правила Nginx сюда не включены.
Существование `mysql_connect()` не подтверждает реальное соединение с БД.

Перед переносом проверить копию базы, сохранение cp1251, публичные URL,
административную часть, загрузки и обработку изображений, cron и зависимости
от Suhosin/XCache. Их наличие в прежней среде не означает, что они реализованы
в новом образе.

Полный Docker-прогон запускается отдельной задачей GitHub Actions. Успешный
прогон runtime не переводит профиль в verified до проверки нужного приложения.
