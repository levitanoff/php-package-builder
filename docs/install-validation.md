# Проверка пакетов перед установкой

Сборка пакетов и обновление сайта — отдельные этапы. Успешная компиляция
и upstream-тесты не подтверждают совместимость приложения или сторонних модулей.

1. Сохрани результаты сборки, версии установленных пакетов, конфигурации
   PHP/Apache/FPM и рабочий способ отката: снимок системы или проверенные пакеты
   вместе с данными, необходимыми для восстановления.
2. Проверь SHA256SUMS и package-manifest.txt. Сопоставь требуемые библиотеки,
   php-common и архитектуру с целевой системой.
3. Выбери нужные пакеты для установленных SAPI/расширений. В полном наборе
   могут присутствовать дополнительные пакеты; весь каталог вслепую не устанавливай.
4. На копии целевой системы выполни симуляцию APT с выбранными локальными `.deb`:
   `apt-get -s install ./имя-пакета.deb ...`. Исследуй удаления, обновления
   библиотек и неудовлетворённые зависимости.
5. Проверь запуск с фактическими php.ini, FPM-pool и конфигурацией Apache,
   загрузку PECL-модулей, обработку HTTP, соединения с БД/Redis, загрузку файлов,
   изображения и значимые операции приложения.
6. Обновляй рабочий сервер с контролируемым перезапуском Apache/FPM.
   Долгоживущие CLI-процессы продолжают использовать старый PHP до завершения
   или перезапуска; учти их бизнес-операции.
7. После переключения проверь версию PHP через каждый HTTP-маршрут/SAPI,
   CLI и обслуживающие процессы, а также журналы ошибок и значимые сценарии.

Конкретная команда установки зависит от состава сервера и проверяется
по симуляции. Этот проект её автоматически не выполняет.
