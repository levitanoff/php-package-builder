# Контракт профиля

Профиль — JSON в `profiles/<id>.json`, один файл на конкретную цель.
Код читает его как данные; shell-файл из профиля не исполняется.

| Поле | Что фиксирует |
| --- | --- |
| `schema_version` | Сейчас `1` |
| `id` | Имя профиля, совпадающее с именем файла |
| `status` | `experimental` или подтверждённый результатами `verified` |
| `php.version` | Полная версия, например `8.3.36` |
| `php.module_api` | Ожидаемый API расширений, проверяемый при сборке |
| `php.package_version` | Собственная версия Debian-пакетов |
| `target` | Семейство, suite, Debian-архитектура, Docker-платформа, образ и APT-источники |
| `source.dsc` | Имя исходного дескриптора |
| `source.files` | Ровно три исходных файла с HTTPS URL, именами и SHA256 |
| `verification.extensions` | Shared-расширения в порядке загрузки: зависимости раньше потребителей |
| `verification.zend_extensions` | Zend-расширения для проверки загрузки |
| `verification.test_paths` | Непустой список upstream-тестов |

Для новой цели копируют близкий профиль и проверяют каждый параметр.
Версия и контрольные суммы берутся из проверенного источника; SHA256 нового
неизвестного файла, вычисленный после скачивания, сам по себе не подтверждает
его происхождение. Нельзя заменять отсутствующую цель готовыми бинарными
пакетами для другой Debian.

В профиле должна быть явно определена версия собственных пакетов. Перед
обновлением сравни её через `dpkg --compare-versions` с установленной версией.
Суффикс сборки меняется при изменениях упаковки, чтобы APT различал результаты.

Поддерживаемые соответствия архитектур в управляющем коде:

| Debian | Docker |
| --- | --- |
| amd64 | linux/amd64 |
| arm64 | linux/arm64 |
| armhf | linux/arm/v7 |

Эта таблица задаёт допустимые соответствия, а не список успешно собранных целей.
В README отражаются только существующие профили и их фактический статус.
Статус `verified` присваивается после полного прогона с сохранением в Git
краткого отчёта в `docs/verification/`: commit, профиль, digest образа,
результаты сборки, проверки пакетов и известные ограничения. Секреты и конфиги
рабочих сайтов в отчёты не включаются.

При исчезновении файла из upstream-репозитория используй сохранённую копию с
тем же SHA256 через `--sources-dir`. Изменение URL при прежних байтах допустимо
после проверки; изменение байтов требует отдельного рассмотрения профиля.
